# SIMS Manager v6.7.97


## v6.7.97 変更点
- 初回セットアップSTEP1で、Search Consoleが正常に開いた場合に「新しいタブを開けませんでした」のフォールバック文が誤表示されないよう修正しました。フォールバックは実際に新規タブを開けなかった場合だけ表示します。
- 「改善の推移」はB列「改善・治療開始日」の降順（新しい順）を標準表示にしました。更新・再生成時と表示時の双方で維持します。
- 「改善履歴」は「改善日」の降順（新しい順）を標準表示にしました。表示時にも順序を整えます。
- 同日の案件は既存順序を維持します。

## v6.7.88 変更点
- aDoctor再診で「追加経過観察」へ移行した時点で、当日の「再診処置」を終了表示・グレーアウトへ同期します。
- Homeの改善効果率は%だけを大きく表示し、件数と「再改善中」は通常文字サイズにします。

- Homeの「改善率」を「改善効果率」へ変更しました。既存記事の改善処置と効果測定対象Mergeを集計し、Creator Direct（新記事）と管理変更履歴は除外します。
- 一度見直し判定を受けた後、新しい観察サイクルが動いている案件を「再改善中」としてKPI欄へ別表示します。

## v6.7.85 変更点

- noindex、非公開・削除、URL変更・リダイレクト、他記事への統合、aMerge吸収記事の301/検索対象外化、管理対象への復帰を「管理変更履歴」として改善履歴へ保存します。
- 管理変更履歴は `モニター状態=COMPLETED`、`観察予定回数=0` とし、改善の推移・7日目/14日目/21日目/28日目の効果測定・改善率には含めません。
- aMerge完了の再送時はイベントキーで重複登録を防止します。

## v6.7.83 変更点

- 旧版でロック状態のまま保存されたaWriter紹介状を「未完了の作業を再開」時に自動再構築します。aDoctor診断のやり直しは不要です。

## v6.7.82 変更点

- aDoctorが `WRITER` / `MERGE` への引継ぎを確定した場合、診断時のワークフローロックを処置側へ持ち越さないよう修正。
- Writer紹介状では正常に `workflow.locked=false` / `treatment_allowed=true` となり、診断時ロック由来の誤BLOCKEDを防止。
- 「今日の改善」で復元された当日終了行に、通常終了行と同じ数値表示（CTR・掲載順位・クリック数・表示回数）と行表示を適用。
- 復元対象の判定・改善フロー・候補選定ロジックは変更しません。

## v6.7.76 変更点

- StarterのF5/onOpen時、System_Log・改善ログ・aDoctor候補など既知の内部／管理シートを直接非表示に同期。
- 全シート走査は追加せず、Home・今日の改善・改善の推移・記事管理・改善履歴など通常利用シートの表示を維持。
- Homeの改善率に、改善完了件数／効果判定済み件数を `80%（16/20件）` の形式で併記します。
- 「SIMS今日の作業」の0番を「HOME画面を更新」に統一し、再集計後にHomeを表示します。

- Homeの改善率で、`COMPLETED`（工程終了）を改善成功として数えていた判定を修正しました。成功は最終判定 `改善完了` のみで集計します。
- 旧データ整合処理で `改善中` を `モニター中` へ一律変換していた処理を停止し、処置中と経過観察中の状態を分離します。

## v6.7.71 変更点

- 改善結果が既に改善履歴へ登録済みの冪等・復旧経路でも、「今日の改善」の該当行を必ず「終了」表示へ同期するようにしました。
- 記事管理が「モニター中」なのに「今日の改善」だけ再診処置のチェックボックスが残る不整合を防ぎます。
- 改善履歴の二重登録は行わず、既存の冪等性を維持します。

## v6.7.69 変更点

- aWriterが `treatment_status: PARTIALLY_COMPLETED` を返した場合、実施済み処置を登録してモニタリングへ進められるようにしました。
- 元のステータスはWriter結果JSONに保持し、完全完了との区別を維持します。

- 本番処理から参照されない旧通信障害テストヘルパーを削除しました。

## v6.7.66 変更点
- GSCデータ0件時は、まずSearch Console・API・Apps Script設定への確認ボタンを表示します。
- 「確認後に再実行」でも0件の場合は、エラーではなく「データ待ち」として約1週間後の再実行を案内します。
- 初回セットアップSTEP2が未完了の場合、Google Cloudプロジェクト番号を空欄で表示します。
- STEP2完了済みの既存環境では、保存済み番号を確認用として表示します。
- 新規利用者が既存値を自分のCloudプロジェクト番号と誤認することを防ぎます。

- 初回セットアップSTEP2を、Google Cloud未経験者でも進められる3段階の案内へ再構成しました。
- ① 標準Google Cloudプロジェクトを作成、② プロジェクト番号を確認してSIMS ManagerのApps Scriptへ関連付け、③ 同じプロジェクトでSearch Console APIを有効化、の順に案内します。
- 既にSIMS用の標準Cloudプロジェクトがある場合は①を省略できます。
- Search Console APIボタンは入力したプロジェクト番号を `project` パラメータへ指定します。

## v6.7.61 変更点

## v6.7.59 変更点

- 期限超過した週次測定が複数残っている場合、1回の日次処理で到来済みの測定回数まで自動キャッチアップします。
- 従来は日次処理1回につき1週分しか進まなかったため、長期未実行案件が「測定待ち（予定日超過）」に残り続ける問題がありました。
- 4回目まで到達した案件は既存の最終判定に従い、「✔️ 完了」または「🔄 再診処置」へ進みます。
- 判定ロジック、今日の改善の優先順位、aDoctor/aWriter Workflowは変更しません。

## v6.7.55 変更点

- 「最終改善完了日」は4回目測定日、「再評価予定日」はその90日後として保存します。
- 4回目測定日時を特定できない記事、既に両日付が正常な記事、完了以外の記事は変更しません。

## v6.7.48 変更点

- 記事管理を作業状態の正本として整理しました。
- `🔥 今日の改善` を記事の作業状態として新規付与しない設計へ変更し、「今日の改善」シートは作業キューとして扱います。
- エース急落を `🚨 急落`、経過観察終了後の要再診を `🔄 再診処置` として記事管理へ明示保存します。
- `🛠️ 処置中` / 治療中 / 診療中は `✏️ 改善中` へ統合します。
- 旧 `🔥 今日の改善` は改善履歴を確認し、再診対象は `🔄 再診処置`、それ以外は `未着手` へ日次処理で移行します。
- 「今日の改善」は `🚨 急落` → `🔄 再診処置` → 通常カテゴリ候補の順で統合し、再診処置は既存 `EFFECT_AFTER_OBSERVATION` からaDoctor再診へ進みます。

詳細は `RELEASE_NOTES_v6.7.46.md` を参照してください。
