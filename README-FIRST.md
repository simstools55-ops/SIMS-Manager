## v6.2.80 変更点

- 未発芽判定式、日次処理、14日ゲート、記事情報更新、Merge処理は変更していません。


## v6.2.77 変更点

- 未発芽記事の主操作を記事詳細へ統合し、「未発芽をaDoctorで精密診断する」を表示するようにしました。
- 記事管理メニューの重複するaDoctor直結操作を削除し、記事状態に応じた主操作へ一本化しました。
- インデックス問題処置の追加診断判定変数欠落を修正しました。
- 未発芽判定式、日次処理、14日ゲート、記事情報更新、Merge処理は変更していません。


## v6.2.75 変更点

- Merge完了画面・進捗表示・完了メッセージの効果測定表現を「7日目・14日目・21日目・28日目」に統一。
- 実際の効果測定登録ロジックは従来どおり4回測定であり、表示文言のみ整合。
- v6.2.74までに修正した未完了作業再開、重複Case整理、Merge完了処理を維持。
- 日次GSC取得、14日ゲート、記事ランク判定、記事情報更新は変更なし。
## v6.2.73 変更点
- aMerge完了時、Case記事が統合先Primaryと一致することを必須にしていた誤判定を修正しました。
- Case記事が `absorbed_article_ids` に含まれる通常のMerge（例：A000156 → A000164）を正常に完了できます。
- 完了後のモニター対象は吸収元Case記事ではなく、統合先Primary記事です。
- 統合先記事・吸収記事を開くボタンをMerge完了画面に維持します。
- 日次GSC取得、14日ゲート、記事ランク判定、記事情報更新は変更していません。

## v6.2.71 変更点
- aDoctorがWAITを返しても、追加診断が明示されている場合は「追加経過観察」へ自動移行しません。
- `CANNIBALIZATION_PRECISION_DIAGNOSIS` / `NEEDS_EVIDENCE` を検出すると「追加診断が必要です」へ分岐します。
- カニバリ精密診断では競合する自サイト記事の本文と180日GSC Evidenceを自動収集し、同一Caseの再診依頼JSONを生成します。
- 追加診断結果は同じaDoctorダイアログから続けて登録できます。
- 記事詳細ダイアログの内側に重複表示されていた「選択記事の詳細」見出しを削除しました。
- 日次GSC取得、14日ゲート、記事ランク判定、完成済みの記事情報更新は変更していません。

## v6.2.63 変更点

- 「記事情報を更新」の6か月クエリ未取得結果を、未発芽へ変更／未発芽のまま／安全照合・保存確認で保留の3状態に分けて集計表示します。
- すでに未発芽だった記事は「未発芽のまま」と明示するため、未発芽へ変更0件でも処置結果が分かります。
- 6か月クエリ取得、安全照合、保存確認、日次処理のロジックは変更していません。

- 記事ランク7区分の合計が記事DB総数と一致するよう修正しました。
- 日次GSC取得・記事ランク判定・aDoctor連携には変更ありません。

## v6.2.55の位置付け

- Homeの記事ランクを「エース → 成長 → 安定 → 育成 → 発芽 → 未発芽 → 未取得」の7区分で表示し、合計を総記事数と一致させます。
- 記事改善の状況は従来どおり全記事の排他6区分で表示します。
- 改善率は右欄KPIとして維持し、算定説明コメントは削除します。
- 改善モニター内訳を「改善が確認できる」「要注意・見直し」「まだ判定できない」の3群に分けます。
- 左列は大きく改善／改善／改善傾向、中央列は変化小／要確認／見直し候補、右列は判定待ち／経過観察／再判定待ち／データ不足です。
- アドバイス欄をモニター表の直下に配置し、表示領域を広く確保します。
- v6.2.51のランク判定閾値、日次GSC取得、サイト健康診断、aDoctor連携は変更しません。
